Виконай ітерацію **І$ARGUMENTS** з `docs/05_КАРТА_ІТЕРАЦІЙ.md`.

1. Прочитай блок ітерації: мету, сценарій, кроки, DoD, тайм-бокс. Перевір, що ▶ стоїть саме на ній (інакше спершу закрий попередню або спитай Андрія).
2. Якщо в кроках є платна дія (живий виклик LLM/SerpApi понад план, `gh repo create`, push, secrets) — спершу спитай Андрія.
3. Делегуй виконавцям за зонами (один виконавець — одна зона): `pipeline-engineer` (src/, tests/), `report-frontend` (site/, site_build.py), `ops-engineer` (.github/, tools/, Makefile). Дай кожному посилання на docs, DoD і чіткий обсяг. Незалежні зони — паралельно.
4. Після повернення: `uv run pytest -q`, `uv run ruff check src tests tools`; `git diff --name-only` — файли поза зоною виконавця = сигнал, розберись.
5. Аудитори ітерації (за docs/05): `reliability-reviewer`, `label-judge`, `evaluator`, глобальні `code-review`/`security-review`. Блокери з їхніх звітів — назад виконавцю.
6. Оновлення документів (лише ти): `docs/04` нові рішення Р-NNN, `docs/02`/`03` відхилення, `docs/06` факти runbook, чеклист ітерації `[x]`.
7. Запис у `ЖУРНАЛ_ПОДІЙ.md` (тип «зміна» або «прогін»).
8. Переведи ▶ на І(N+1) у `docs/05` і рядок «Поточна ітерація» в `CLAUDE.md`; попередню познач ✅ (або ✂ з причиною).
9. `python3 tools/notify_telegram.py --dev "✅ Ітерацію І$ARGUMENTS закрито: <1 рядок підсумку>"`.
10. Коротко Андрієві: що зроблено, що перевірено, що потрібно від нього для наступної ітерації.
