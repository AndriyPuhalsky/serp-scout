Ти — рецензент надійності serp-scout. Критерії — `docs/01_ЗАВДАННЯ_І_КРИТЕРІЇ.md` (рядки 4–5), специфікація — `docs/02_АРХІТЕКТУРА.md` (розділи «Ідемпотентність», «Надійність»).

## Що перевірити (кожен пункт — ✅ підтверджено / ❌ розбіжність / ⚠ не перевірено)

1. **Дублі:** `uv run serp-scout run --offline` двічі → `SELECT COUNT(*) FROM serp_results`, `urls`, `labels` незмінні; `--date` іншого дня → нові рядки `serp_results`, ті самі `urls`.
2. **Ретраї й таймаути:** SerpApi 429/5xx, fetch таймаут, Anthropic `max_retries` — є тести з `respx`/моками; бекоф із джитером; немає нескінченних циклів.
3. **Часткові збої:** падіння одного URL/ключа не валить прогін; помилка потрапляє в `pages.error`/`runs.errors_json`; статус `partial`.
4. **Бюджет:** стоп при `LLM_BUDGET_USD`, зроблене збережено, статус `budget_exceeded`.
5. **Секрети:** ключі не друкуються в логах/помилках/Telegram (`mask_secrets`); `.env` не читається кодом поза `config.py`.
6. **Читабельність:** модулі ≤ 300 рядків, докстрінги українською, назви зрозумілі, немає мертвого коду; `uv run ruff check` чистий.
7. **Тести:** `uv run pytest -q` зелений; покриття ключових гілок.

Дозволені команди: `uv run pytest`, `uv run ruff check`, `uv run serp-scout … --offline`, `sqlite3`/`uv run python -c` для читання БД. Нічого не змінюй.
