# 08 — Карта харнесу

Принцип: **агенти = ролі (хто), скіли = знання (як), команди = сценарії (коли), хуки = правила (завжди)**. Головна сесія — оркестратор: читає docs, делегує виконавцям, перевіряє аудиторами, єдина пише `docs/`, журнал, `CLAUDE.md`, `.claude/`.

## Ролі й зони

| Агент | Роль | Зона запису | Модель |
|---|---|---|---|
| `pipeline-engineer` | виконавець | `src/`, `tests/` | opus/high |
| `report-frontend` | виконавець | `site/` (крім `site/data`), `site_build.py` | opus/high |
| `ops-engineer` | виконавець | `.github/`, `tools/`, `netlify.toml`, `Makefile` | opus/high |
| `label-judge` | аудитор критерію 2 | — (звіт) | opus/high |
| `reliability-reviewer` | аудитор критеріїв 4–5 | — | inherit/high |
| `evaluator` | аудитор критерію 1 і бонусу | — | sonnet/medium |

Глобальні: `design-scout`, `code-review`, `security-review`, `claude-api`, `dataviz`, `claude-in-chrome`.

## Команди (`.claude/skills/*`, лише вручну)

`/status` · `/iterate N` · `/run` · `/qa labels|site|readme` · `/publish` · `/commit` · `/log` · `/notify` · `/cost` · `/incident` · `/video` · `/submit`. Скіли-знання (модель підтягує сама): `serp-scout-domain`, `serpapi`, `daily-automation`, `report-design` (з І4).

## Конвеєр ітерації

`/iterate N` → читає `docs/05` → виконавці за зонами (паралельно, якщо незалежні) → хуки ганяють тести після кожної правки → аудитори → `git diff --name-only` поза зоною = сигнал → оркестратор оновлює docs і журнал → ▶ на N+1 → Telegram.

## Хуки (`.claude/hooks/`, stdlib, тести `tests/test_hooks.py`)

| Хук | Подія | Правило |
|---|---|---|
| `session_context` | SessionStart | дедлайн, ▶ ітерація, журнал, ключі (назви), снапшот, витрати |
| `guard_outside` | PreToolUse Write/Edit | запис лише в проєкт (+scratchpad, memory) |
| `guard_secrets` | PreToolUse Write/Edit, `git commit` | жодних ключів у файлах і комітах |
| `guard_generated` | PreToolUse Write/Edit | `site/data`, `data/export`, `serp.sqlite`, `docs/10` — лише генератори |
| `post_edit_tests` | PostToolUse Write/Edit | ruff + pytest / test_hooks / node --test за зоною |
| `docs_lint` | PreToolUse `git commit` | ▶ узгоджено, Р-NNN/#NNN без дублів, frontmatter, README ≤ 1 стор. |
| `journal_reminder` | Stop | без запису в журнал не завершуємо |
| `notify_stop` | Stop (async) | Telegram «⏹ Сесія: …» |
| `notify_attention` | Notification (async) | Telegram «⏸ Claude чекає на вас» |

Урок І0 (Р-012): хуки в `settings.json` підхоплюються миттєво — файли хуків мають існувати **до** запису settings, інакше всі інструменти блокуються.

## Безкоштовне vs платне: де платне дало б кращу якість

| Складова | Безкоштовно (обрано) | Платно | Різниця в якості |
|---|---|---|---|
| SERP | SerpApi Free (≈ 100/міс) | SerpApi Starter $25 / DataForSEO ≈ $0.002–0.006 за SERP | **даних — ні**, те саме API; платне = обсяг (10 ключів щодня = 300/міс) і в DataForSEO точніша гео/ОС |
| Завантаження сторінок | httpx + Jina Reader | Zyte / ScrapingBee / Bright Data ≈ $1–3 за 1k | **так**: частина казино-сайтів за Cloudflare → у нас лише snippet-розмітка з низькою впевненістю; анлокери дають ≈ 95 %+ покриття |
| LLM | Sonnet 5.5 | Opus 5.5 (≈ ×2), Batches −50 % | **так, помірно**: Opus точніший на неявних контактах і брендах |
| Сховище/UI | SQLite + статичний сайт | Supabase / Google Sheets | якість даних — ні; зручність для багатьох менеджерів — так |
