# 02 — Архітектура продукту

Чистий Python 3.13 + `uv`; продукт не залежить від Claude Code (харнес лише організовує розробку). Секрети — лише в `.env` (локально) і GitHub Secrets (Actions).

## Потік одного прогону (`serp-scout run`)

```
config/keywords.yml ─► providers (serpapi | fixture) ─► store.upsert_snapshot (снапшот дня)
                                                            │
                               unique urls без pages ◄──────┘
                                      │
                              fetch (httpx mobile UA → r.jina.ai → snippet) ─► extract (trafilatura, email/контакти)
                                      │
                              labeler (Claude Sonnet 5.5, structured output, кеш, бюджет-стоп) ─► brands (нормалізація)
                                      │
                              store (labels, pages, runs з вартістю) ─► export (CSV/JSON) ─► build-site (report.json)
```

Режими: `--offline` (фікстури SerpApi + касети LLM, без ключів; пише в `data/demo/`), `--limit N` (перші N URL до LLM), `--limit 0` (лише SERP), `--no-llm`, `--skip-serp` (на наявному снапшоті дня, без SerpApi), `--date YYYY-MM-DD` (снапшот за іншу дату — для тестів історії), `--relabel` (перерозмітити навіть за наявності кешу), `--refetch` (перезавантажити сторінки). Google-редиректи `google.*/goto?url=` розгортаються до цільової адреси перед нормалізацією.

## Модулі `src/serp_scout/`

| Модуль | Відповідальність |
|---|---|
| `cli.py` | typer: `run`, `export`, `build-site`, `labels` (показати розмітку), `resolve-redirects [--demo]` (домен для `google.*/goto`), `resolve-links` (бонус), `stats` |
| `config.py` | завантаження `config/*.yml` + `.env` (python-dotenv), `Settings`; `mask_secrets()` |
| `providers/base.py` | `SerpHit(position, url, title, snippet)`; `SerpProvider.search(keyword) -> list[SerpHit]` |
| `providers/serpapi.py` | SerpApi `engine=google, location=Canada, gl=ca, hl=en, device=mobile, num=10`; сира відповідь → `data/raw/<дата>/<id>.json`; ретраї на 429/5xx/таймаут (tenacity, бекоф + джитер) |
| `providers/fixture.py` | читає `tests/fixtures/serp/<id>.json` (формат SerpApi) |
| `store.py` | схема SQLite, upsert без дублів, історія, представлення |
| `fetch.py` | мобільний UA iPhone, таймаут 15 с, 2 ретраї, ліміт 2 МБ, 4 паралельно, 1 с на домен; фолбек `https://r.jina.ai/<url>` на 403/503/капчу/порожній текст; останній фолбек — title+snippet із SERP (`method=snippet`) |
| `extract.py` | trafilatura → текст; email-регекс із деобфускацією (`[at]`, `(dot)`), `mailto:`, посилання contact/advertise/write-for-us/about/media-kit; усічення «9k голова + 3k хвіст» |
| `labeler.py` | Sonnet 5.5 через `client.messages.parse()` з pydantic-схемою; збій розбору/refusal → один повтор із `max_tokens × 2`, інакше мітка «збій розмітки» (`needs_review=true`, не кешується); кеш за `(url_id, prompt_version, text_hash)`; вартість з `usage` × ціни; **стоп при `LLM_BUDGET_USD`** → `runs.status = budget_exceeded`, решта — наступним прогоном |
| `brands.py` | нормалізація за `config/brands.yml` + вільні назви від LLM |
| `links.py` | бонус І6 (зарезервовано: таблиця `affiliate_links`, `LinksSettings`, `urlnorm.registered_domain` уже є): партнерські посилання → ланцюжок редиректів (≤ 10) → фінальний домен → бренд |
| `export.py` | `data/export/serp_<дата>.csv`, `labels.csv`, `history.csv` |
| `site_build.py` | `site/data/report.json` для сайту |
| `costs.py` | `data/costs.jsonl` (рядок на LLM-виклик) і підсумки для `stats` |

## Модель даних (SQLite `data/serp.sqlite`, у git)

```sql
keywords(id PK, keyword TEXT UNIQUE, cluster TEXT)
runs(id PK, run_date TEXT, started_at, finished_at, status TEXT,   -- ok | partial | budget_exceeded | failed
     mode TEXT, serp_calls INT, urls_total INT, urls_new INT, pages_fetched INT, pages_failed INT,
     labels_new INT, input_tokens INT, output_tokens INT, cost_usd REAL, errors_json TEXT, git_sha TEXT)
serp_results(id PK, run_date TEXT, keyword_id INT, position INT, url_id INT, title TEXT, snippet TEXT,
     UNIQUE(run_date, keyword_id, position))                       -- це і є історія позицій
urls(id PK, url TEXT UNIQUE, domain TEXT, first_seen TEXT, last_seen TEXT, best_position INT)
pages(url_id INT UNIQUE, fetched_at TEXT, method TEXT,              -- httpx | reader | snippet
      final_url TEXT,                                               -- кінцева адреса після редиректів httpx (goto → сайт)
     http_status INT, text_hash TEXT, text_len INT, text_path TEXT, emails_json TEXT, contact_links_json TEXT, error TEXT)
labels(id PK, url_id INT, prompt_version TEXT, text_hash TEXT, site_type TEXT, relevant INT, confidence REAL,
     reason TEXT, brands_json TEXT, contact_json TEXT, placement_signals_json TEXT, needs_review INT,
     model TEXT, input_tokens INT, output_tokens INT, cost_usd REAL, labeled_at TEXT,
     UNIQUE(url_id, prompt_version, text_hash))
affiliate_links(id PK, url_id INT, href TEXT, anchor TEXT, final_url TEXT, final_domain TEXT, brand TEXT,
     hops INT, resolved_at TEXT, error TEXT, UNIQUE(url_id, href))
-- представлення: v_latest (останній снапшот + остання розмітка на URL), v_history (позиції по датах)
```

**Ідемпотентність.** Той самий день → `INSERT OR REPLACE` снапшота дня (рядки `serp_results` за `run_date` перезаписуються, не дублюються). Інший день → новий снапшот = нова точка історії. `urls` — upsert за `url` (оновлює `last_seen`, `best_position`). `pages` і `labels` не повторюються, якщо `text_hash` і `prompt_version` не змінились; `--refetch`/`--relabel` — свідомо. Домен — `tldextract` (офлайн-снапшот суфіксів), `www.` знято. Для непрозорих `google.*/goto?url=CAES…` (SerpApi mobile) `urls.url` лишається goto-адресою (ключ дедуплікації, `url_key`, історія), а `domain` і `pages.final_url` беруться з кінцевої адреси httpx-редиректу (`store.apply_final_url` у pipeline; для наявних рядків — `serp-scout resolve-redirects`). Офлайн-демо goto не розгортає (Р-028).

**Надійність.** Збій одного URL/ключа не валить прогін: помилка → `pages.error` / `runs.errors_json`, статус `partial`. Деградація завантаження до `method=snippet` — не збій (сніпет — валідні дані): пишеться `pages.error` з причиною і рахується в `pages_failed`, статус лишається `ok`. Ретраї: SerpApi (3 спроби, бекоф 2–8 с), fetch (2 ретраї), Anthropic SDK (`max_retries=3`). Таймаути всюди. У логах і Telegram секрети замасковано.

## Щоденний прогін і публікація

`.github/workflows/daily.yml`: cron 09:00 Київ + запасний 10:30; `workflow_dispatch(force, limit)`; `concurrency: daily`; `permissions: contents: write`; кроки: checkout → setup-uv → `uv sync --frozen` → сторож «снапшот за сьогодні є?» → `run` → `export` → `build-site` → артефакт `data/raw/<дата>` (7 днів) → коміт `data/serp.sqlite data/export site/data` через `tools/commit_push.sh` (без `[skip ci]` — Netlify пропускає деплой з таким тегом; `daily.yml` не слухає `push`, тож зациклення немає) → Telegram ✅/❌. Netlify підхоплює push (publish `site`, без збірки).
